# 保险产品知识库(Phase 1)

主流保险公司在售 **重疾险 / 医疗险(百万医疗) / 意外险** 产品结构化数据。

- 数据抓取日期:**2026-09-08**;缺口补齐与复核:**2026-09-10**(15 款记录经二次核实,带 `last_verified` 标记)
- 产品总数:**28 款**(重疾 11 / 医疗 10 / 意外 7)
- 构建方式:三路并行网络调研 + 一轮定向补缺,来源优先级为 官方公开信息披露(条款/费率表)→ 保险行业协会产品库 → 权威测评/销售平台页,每个关键数字带出处 URL 与置信度
- 主要指标完整性:品牌(承保公司)28/28、医疗险保证续保 10/10、保障范围关键字段全量、价格 25/28(余 3 款经穷尽排查确认无公开可靠口径)

## 字段说明

**公共字段**(三个类别通用):

| 字段 | 说明 |
|---|---|
| `product_id` | CI-xx / MED-xx / ACC-xx |
| `product_name` | 含版本号/年份,换代频繁,以版本名为准 |
| `company` | 承保公司全称(注意与销售平台/品牌区分,见下方易错点) |
| `channel` | 个险 / 电销 / 银保 / 互联网(平台名) |
| `status` / `status_evidence` | 在售判断及依据 |
| `underwriting_age` | 投保年龄范围 |
| `guarantee_period` | 保障期间 |
| `waiting_period` | 等待期(重疾险常见 90/180 天;医疗险 30/90 天;意外险通常无) |
| `hesitation_period` | 犹豫期 |
| `premium_reference` | 参考保费,**必须连同 `assumption` 口径一起看** |
| `confidence` | high=官方条款/费率核实;medium=权威测评+官方页交叉;low=仅搜索摘要 |
| `data_completeness` | 该产品字段填充比例(0-1) |

**分类专属字段**(`coverage` 对象内):

- 重疾险:`severe_illness` / `moderate_illness` / `mild_illness`(病种数、比例、次数)、`special_extra`(额外赔)、`death_benefit`、`waiver`(豁免)
- 医疗险:`renewal`(续保条件,**最重要指标之一**:是否保证续保/保证几年/费率可调)、`general_medical_limit`、`critical_medical_limit`、`deductible`、`reimbursement_ratio`、`special_drug`、`proton_therapy`、`value_added`
- 意外险:`accidental_death`、`disability`、`accidental_medical`、`hospital_subsidy`、`transport_extra`、`sudden_death`

## 保费口径(重要)

不同来源口径不一致,数字**只能横向对比同口径产品**,以 `premium_reference.assumption` 文字为准:

- 重疾险目标口径:30 岁 / 50 万保额 / 30 年缴 / 保终身 / 基础责任。实际:平安(官方费率换算)、达尔文 12 符合;泰康为 20 万 20 年缴、人保为 30 万 19 年缴全责任,不可直接比
- 医疗险:30 岁有社保首年(友邦传世无忧为高端医疗历史版本参考价,量级不同)
- 意外险:主销档位年缴(多为 18-50 岁统一费率,少儿款 0-17 岁统一价)

## 长期方案:定时抓取知识库(建议架构)

Phase 2 目标:定时任务自动检测产品换代/停售/费率调整。建议:

1. **数据源清单化**(本库 source_urls 已是种子):官方信息披露页(平安/太保/新华/泰康/众安/国寿可直连)+ 平台页(蚂蚁保/微保/慧择/小雨伞)+ 行业协会产品库
2. **抓取层**:Python + httpx/Playwright(JS 渲染页);官网 PDF 条款/费率表下载归档到 `artifacts/` 按日期快照
3. **解析层**:条款 PDF → 结构化字段(等待期/病种数/免赔额正则+LLM 抽取);费率表 PDF → 年龄×保额费率矩阵存 SQLite
4. **存储**:`products.json` 升级为 SQLite(表:products / versions / premiums / sources),每次抓取生成新 version 快照而非覆盖
5. **变更检测**:新旧快照 diff,输出"换代/停售/涨价"报告;建议频率:**互联网爆款每月 1 次**(换代极快,如超级玛丽 15→16 仅隔数月),传统个险产品每季度 1 次
6. **调度**:macOS launchd 或 crontab,如 `0 9 1 * *`(每月 1 日);每次跑完输出 diff 报告
7. **合规**:仅采集公开披露信息,尊重 robots/频率限制;使用时注明"以官方条款为准"
