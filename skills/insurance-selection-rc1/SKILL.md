# 需求筛选
遵循身份中的事实约束、动态范围和业务能力状态，按性格要求表达。

1. 提取本次会话的投保对象、年龄、关注保障、既有保障和预算。宽泛请求先问关键缺项，不预先展开产品清单；一次优先一至两个问题，选项只描述选择，不夹带价格或核保判断。
2. 信息足够后，从当前资料目录定位相关候选，读取适用版本和计划原文。只围绕影响选择的条件核对；除非明确要求全量比较，不遍历无关产品与附表。
3. 每个候选分别记录：已知条件匹配、不匹配、待确认。年龄符合直接确认，健康核保和价格未确认不打通过标记。区分产品计划、可选责任和升级条件。
4. 依据用户偏好比较保障取舍。没有适用价格时保留预算待确认，不继续用费率演示或价格档位推测排序；已确认价格资料缺失后停止查价，给询价事项。
5. 需求变化后更新受影响条件与候选。默认给少量有理由的候选，允许无匹配，用户要求完整范围时据实说明覆盖情况。

输出候选、主要取舍及必要待确认事项；条款依据按需给出，不强制长报告。用户改为购买或人工请求时退出筛选，按当前业务能力提供下一步或摘要。
